# Learning Flow Reliability and Free Shopping Design

## Goal

แก้ความถูกต้องและความชัดเจนของเส้นทางเรียนตั้งแต่การจัดการนักเรียนถึง Level 5 โดยให้เสียงภาษาไทยทำงานได้โดยไม่พึ่ง Web Speech API และเปลี่ยน Level 5 เป็นแบบฝึก 4 สถานการณ์ตามโจทย์ตามด้วยการเลือกซื้ออิสระ 1 รอบ

## Scope

- เพิ่มการลบนักเรียนจากกล่องนักเรียน พร้อมยืนยันก่อนลบ
- แก้ Pretest ให้ตรวจโจทย์ที่สุ่มอยู่จริง และไม่แสดงคำใบ้เมื่อตอบถูก
- ให้ Pretest รอเสียงตอบรับหรือคำใบ้จบก่อนเปลี่ยนข้อ
- เพิ่มไฟล์เสียงภาษาไทยจริงสำหรับโจทย์ใน Level 2, Level 3 และ Level 4
- ทำสถานะตัวเลือกที่เลือกใน Level 4 ให้เห็นชัด
- ปรับ Level 5 เป็น 4 guided rounds และ 1 free-shopping round
- เก็บข้อมูลการทำแบบฝึกเดิมต่อเนื่อง รวมคะแนน เวลา จำนวนครั้งที่ผิด และคำตอบรายข้อ

## Student Deletion

แต่ละ student card มีปุ่มลบที่แยกจากพื้นที่เลือกนักเรียนอย่างชัดเจน ปุ่มใช้ชื่อที่เข้าถึงได้ว่า `ลบนักเรียน <ชื่อ>` เพื่อไม่ให้การกดลบเลือกนักเรียนโดยไม่ตั้งใจ

เมื่อกดลบ ระบบแสดง dialog ยืนยันที่ระบุชื่อนักเรียนและอธิบายว่าคะแนน ความก้าวหน้า Pretest และประวัติการทำแบบฝึกจะถูกลบด้วย การยืนยันจึงเรียก storage API เพียงจุดเดียวเพื่อทำ cascade deletion กับ:

- `students`
- `progress`
- `assessments`
- `attempts`
- `current_student` เมื่อเป็นคนเดียวกับที่ถูกลบ

หลังลบ รายการบนหน้าจออัปเดตทันที หากนักเรียนที่ถูกเลือกถูกลบ ปุ่มเริ่มเรียนกลับสู่สถานะ disabled

## Pretest Correctness and Audio Sequencing

Pretest ต้องใช้ `currentQ` จากรายการ `questions` ที่สุ่มแล้วสำหรับการตรวจคำตอบ การสร้าง attempt และการเลือก hint ห้ามอ้าง `QUESTIONS[currentIndex]` เพราะตำแหน่งหลังสุ่มไม่ตรงกับชุดต้นฉบับ

การตอบถูกแสดงเฉพาะข้อความถูกต้องและไม่มีคำว่า `คำใบ้` การตอบผิดแสดงและอ่าน hint ของ `currentQ` เท่านั้น

เพิ่ม audio API ที่คืน Promise และ resolve เมื่อไฟล์เสียงเกิด `ended` หากไฟล์โหลดหรือเล่นไม่ได้ ให้ fallback อย่างปลอดภัยและ resolve หลังเวลาสำรองที่กำหนด หน้า Pretest จะรอ Promise นี้ก่อน reset state และขยับไปข้อถัดไป ปุ่มและตัวเลือกยัง disabled ระหว่างรอเพื่อป้องกันการกดซ้ำ

เสียงเลือกเหรียญและธนบัตรไม่บล็อก flow มีเฉพาะเสียงผลลัพธ์หรือคำใบ้หลังยืนยันเท่านั้นที่ต้องรอให้จบ

## Level 2–4 Question Audio

Chrome ในสภาพแวดล้อมใช้งานไม่มี `speechSynthesis` ดังนั้นข้อความโจทย์แบบ dynamic ต้องมีไฟล์เสียง `.m4a` ที่ map ด้วยข้อความ exact match ใน `THAI_RECORDINGS`

- Level 2: เสียงโจทย์สินค้าและราคา 5 ข้อ
- Level 3: เสียงโจทย์สินค้า ราคา และคำสั่งเลือกเงิน 5 ข้อ
- Level 4: เสียงโจทย์รวมราคาสินค้า 5 ข้อ และเสียงคำสั่งเลือกเงินตามยอดสำหรับขั้นจ่ายเงิน

เมื่อเปลี่ยนโจทย์หรือเปลี่ยนขั้น ระบบเรียก `speakThai()` ด้วยข้อความเดียวกับที่ใช้เป็น key ใน recording map ทุกครั้ง Tests ต้องตรวจ exact string เพื่อป้องกันข้อความหน้า UI และไฟล์เสียงไม่ตรงกัน

## Level 4 Selected State

ตัวเลือกผลรวมที่ถูกเลือกต้องต่างจากตัวเลือกปกติด้วยหลายสัญญาณ ไม่อาศัยสีอย่างเดียว:

- พื้นสีส้มเข้มและตัวอักษรสีขาว
- กรอบสีส้มเข้มและวงแหวนรอบนอก
- แสดงเครื่องหมาย `✓` พร้อมข้อความ `เลือกแล้ว`
- ใช้ `aria-pressed=true`
- ยกตำแหน่งขึ้นเล็กน้อยและเพิ่มเงา

ตัวเลือกที่ยังไม่เลือกคงพื้นสีอ่อนและไม่มีเครื่องหมายเลือก

## Level 5 Hybrid Shopping

Level 5 มีทั้งหมด 5 รอบ:

1. Guided round 1
2. Guided round 2
3. Guided round 3
4. Guided round 4
5. Free-shopping round

### Guided rounds

ระบบสุ่ม 4 สถานการณ์จากคลัง 4 สถานการณ์โดยเปลี่ยนลำดับในแต่ละครั้ง แต่ละรอบกำหนดร้านและสินค้าที่ต้องเลือก จากนั้นเด็กเลือกเงินให้ครบยอดเหมือน flow เดิม

### Free-shopping round

รอบสุดท้ายแสดงข้อความ `รอบเลือกซื้อเอง` และไม่กำหนดร้านหรือสินค้า เด็กทำตามลำดับ:

1. เลือกร้านหนึ่งร้าน
2. เลือกสินค้าในร้านนั้นอย่างน้อยหนึ่งชิ้น เด็กเลือกหลายชิ้นได้ แต่สินค้าแต่ละรายการเลือกได้หนึ่งชิ้น
3. ยืนยันสินค้าเพื่อคำนวณยอดรวม
4. เลือกเหรียญหรือธนบัตรแบบตัวคูณและกดจ่ายเงิน

การเลือกร้านใหม่ก่อนยืนยันสินค้าจะล้างสินค้าที่เลือก เพื่อไม่ให้มีสินค้าจากคนละร้านปะปนกัน ปุ่มยืนยัน disabled จนกว่าจะเลือกข้อมูลขั้นต่ำครบ

การจ่ายเงินครบยอดถือว่ารอบอิสระสำเร็จและ Level 5 สำเร็จ รอบอิสระเก็บ `activity_type` หรือ step metadata ที่ระบุ `free_shopping` พร้อมร้าน รายการสินค้า ยอดเงิน คำตอบ เวลา และจำนวนครั้งที่ผิด Dashboard จึงแยกรอบนี้จาก guided rounds ได้

## Scoring and Analytics

คะแนน Level 5 เต็ม 5 คะแนน รอบละ 1 คะแนนเมื่อทำสำเร็จโดยไม่เคยยืนยันผิดในรอบนั้น การตอบผิดแล้วแก้สำเร็จยังเดินต่อได้ แต่ไม่ได้ first-try point สำหรับรอบนั้น

Attempt เดียวเก็บ answers 5 รายการตามลำดับที่ทำจริง รายการรอบอิสระใช้ prompt ที่สรุปสิ่งที่เด็กเลือกจริงหลังยืนยันสินค้า เช่น ร้าน สินค้า และยอดรวม เพื่อให้ Dashboard อ่านได้โดยไม่ต้องตีความ state ภายในหน้า

## Error Handling

- การยืนยันโดยยังไม่เลือกคำตอบไม่ทำงาน
- Audio promise ต้อง resolve แม้ไฟล์เล่นไม่ได้ เพื่อไม่ให้หน้าเรียนค้าง
- การลบนักเรียนที่ไม่มีอยู่แล้วเป็น idempotent และไม่ลบข้อมูลของนักเรียนอื่น
- Free shopping ไม่อนุญาตสินค้าเป็นศูนย์รายการหรือยอดรวมเป็นศูนย์
- เงินที่จ่ายไม่ตรงยอดแสดงและอ่านคำใบ้ exact match จากไฟล์เสียงที่รองรับ

## Testing

ใช้ TDD โดยเขียนและรัน failing tests ก่อนแก้ production code:

- Storage test: cascade deletion และไม่กระทบนักเรียนอื่น
- Student selection test: ปุ่มลบ, dialog ยืนยัน, ยกเลิก และ state หลังลบ
- Pretest tests: shuffled question correctness, no hint on correct, wait for audio completion before advancing
- Speech tests: promise resolves on `ended` และ fallback error/timeout
- Level 2–4 tests: prompt exact match กับ bundled recording
- Level 4 test: selected option มี `aria-pressed`, check indicator และ selected classes
- Level 5 tests: guided 4 รอบ, free round เป็นรอบที่ 5, เลือกร้าน/สินค้าเอง, คำนวณยอด และบันทึก free-shopping analytics
- Full suite, ESLint และ production build

## Out of Scope

- การ sync ข้อมูลขึ้น backend
- จำนวนสินค้ามากกว่าหนึ่งชิ้นต่อ SKU ใน free shopping
- การเพิ่มร้านหรือสินค้าใหม่จากหน้าครู
- การเปลี่ยนเกณฑ์ปลดล็อก Level อื่น
